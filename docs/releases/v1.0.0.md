# TripForge v1.0.0

TripForge v1.0.0 is the first formal application/source release. It freezes the
documented product behavior and deployment artifact identity; it does not turn
the private TypeScript workspaces into public npm APIs or claim a production
launch.

## Highlights

- Collaborative travel planning with owner/editor/viewer RBAC.
- Accessible itinerary planning with pointer, keyboard and explicit Move flows.
- Realtime collaboration, shared expenses, private documents and PostgreSQL
  search.
- A private, grounded AI assistant with read-only tools and reviewable proposals.
- Production-oriented testing, security, observability, resilience and delivery.

## Product capabilities

Trips combine destinations and dated Days with itinerary activities, routes,
reservations, per-currency expenses and settlements, private file transfer,
durable notifications, scoped search and permission-aware realtime freshness.
The assistant can explain Trip state and propose changes, but normal domain code
and explicit approval remain the mutation boundary.

## Engineering highlights

PostgreSQL commits are authoritative; Redis carries invalidations and queued
work. A transactional outbox makes object cleanup recoverable. Trusted CI builds
web, API/worker and migration OCI images, publishes immutable digest identities,
and produces BuildKit SBOM and max-mode provenance. The complete architecture
and trade-offs are in the [engineering case study](../portfolio-case-study.md).

## Verification

Retained Stage 31/32 evidence includes 12 Chromium E2E scenarios without retry
masking, 98 PostgreSQL/Testcontainers integration tests, 13 local readiness and
recovery drills, and a 30-minute local soak with 100 concurrent Socket.IO clients
and 0% unexpected HTTP errors. Stage 32's final closure harness passed 26/26.
These are scoped local results, not hosted GitHub or production-traffic claims.
See [Stage 31 qualification](../stage31-qualification.md),
[Stage 32 verification](../stage32-verification.md) and the
[Stage 33 release record](../stage33-release-verification.md).

## Security status

`GHSA-vfj7-8cjw-p6xm` / `CVE-2026-93687` affects `braces@3.0.3` only through
development ESLint/build tooling. It is absent from the final web, API/worker and
migrate runtime images and browser chunks. The exact exception is reviewed
through 2026-11-01 and fails closed afterward or if identity, dependency path or
reachability changes. Fixable HIGH/CRITICAL runtime-image findings are blocking;
the runtime images include Debian's fixed `libpcre2-8-0 10.42-1+deb12u2`
revision for `CVE-2026-103111`, and fresh scans report zero remaining fixable
HIGH/CRITICAL findings. The remaining 52 HIGH/4 CRITICAL base-image findings per
image are unfixed and monitored rather than described as harmless. Details:
[security policy](../security-hardening.md) and
[Stage 32 proof](../stage32-verification.md).

## Known limitations

- AWS infrastructure is implemented and statically validated; real AWS deploy,
  PITR, ElastiCache failover and ECS rollback qualification are pending.
- Live OpenAI, ORS and MapTiler provider qualification remains pending where
  credentials/environments are unavailable.
- Manual VoiceOver/Safari, 200%/400% zoom and text-spacing checks remain pending.
- Stage 31's small client/harness heap median drift remains under observation; it
  is not a confirmed memory leak.
- The time-bounded `braces` development-tool exception must be re-reviewed before
  publication after 2026-11-01.

## Deployment status

This source release does not imply a live service. No AWS resources are created
by release publication. A later authorized deployment should consume the exact
web, API and migrate `@sha256` references from the trusted release manifest; the
worker uses the API digest with `node dist/worker.js`.
